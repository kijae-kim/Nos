# 프로필 묶음: 사진·이모지·내 색 설계

2026-11-17 · 상태: 검토 반영, 승인 대기 · 앞: 캘린더 묶음 · 다음: 앨범 사진 핀

## 왜

지금 두 사람의 모습은 색 동그라미뿐이고, 그 색도 **보는 사람 기준**이다(나는 늘 코랄 `av a`, 상대는 늘 파랑 `av b`). 그래서 사람마다 정해진 모습이 없다. 사용자는 각자 프로필을 사진이나 이모지로 정하고 싶어 한다. 일정의 "나" 표시에는 사진이 아니라 **사람마다 고른 색**을 쓰고 싶어 한다(사용자: "프로필 사진을 변경해도 등록한 일정에서 '나'라고 나오는 부분에 사진으로 나오지 않게 … 사용자가 설정한 색").

## 목표

1. 각자 **프로필**을 정한다: 사진 올리기 / 이모지 고르기 / 내 색.
2. 동그라미(아바타)는 **사진 > 이모지(내 색 바탕) > 내 색** 순서로 보인다. 두 사람 화면에서 같은 사람은 같은 모습.
3. 일정 목록의 만든 사람 표시는 **그 사람 색 점 + 이름**(`● 나`, `● 바다`). 사진은 쓰지 않는다.

## 하지 않는 것

- AI 로 사진을 이모지·그림으로 바꾸기 (유료).
- 사진 원본 보관, 자르는 위치 고르기(가운데 정사각형으로 자동).
- 많이 쓴 태그로 표시하기 (사용자가 색을 고름).

## 이러면 실패

- 다른 커플 사람의 프로필 사진을 주소로 볼 수 있다.
- 올린 사진에 위치(EXIF GPS)가 남는다.
- 두 사람이 같은 색이라 일정에서 누가 만든 건지 모른다.
- 프로필 사진 때문에 R2·Neon 무료 한도에 영향이 생긴다.

## 제약

- 모델이 바뀐다(`accounts` 앱) → **Neon migrate 먼저**, 확인 숫자 **53** (데이터 마이그레이션으로 기존 사람 색을 채우는 것까지 한 파일).
- 문구 존댓말, 색은 토큰(`var(--<색>)`), 375px·라이트/다크·배/여정.
- Vercel 요청 4.5MB 한도: 브라우저가 256px 로 줄여 보내므로 문제없음. 서버는 원본 파일 2MB 까지만 받는다(브라우저가 못 줄였을 때 대비).

## 방법 (고려한 것)

| 질문 | 고른 것 | 다른 길 |
|---|---|---|
| "나" 표시 | **각자 고른 색** (사용자) | 많이 쓴 태그: 저절로 바뀌고 이름표 없으면 빈칸 |
| 사진 저장 | **DB 에 256px JPEG(20KB 안팎)로, 우리 주소로 보여 주기** (사용자) | R2: 서명 주소가 1시간마다 바뀌어 매번 다시 받음, 용량 기록·한도 검사 필요 |
| 처음 색 | **먼저 가입한 사람 장미, 상대 하늘** (내 판단, 지금 코랄·파랑과 비슷) | 둘 다 같은 기본색 |
| 같은 색 | **상대가 쓰는 색은 못 고름** (내 판단) | 허용 |

## 설계

### 저장 (`accounts.User`, 마이그레이션 `accounts.0004_profile` → Neon 53)

- `color = CharField(10, choices=COLOR_CHOICES, default="sky")` — `COLOR_CHOICES` 는 couples 와 같은 6색(sky·rose·sand·lav·sage·peach). 순환 import 를 피해 accounts 쪽에 같은 목록을 두거나 couples 에서 가져온다(빌더 판단).
- `emoji = CharField(16, blank=True)`.
- `avatar = BinaryField(null=True, blank=True, editable=False)` — 256×256 JPEG 바이트.
- `avatar_version = PositiveIntegerField(default=0)` — 바꿀 때마다 +1, 주소 끝 `?v=` 로 캐시 무효화.
- 데이터 마이그레이션: 커플마다 `date_joined`(같으면 pk) 순으로 첫 사람 `rose`, 둘째 `sky`. 커플 없는 사람은 `rose`.
- 새로 커플에 들어오는 사람(초대 코드 연결): 상대 색과 다르면 그대로, 같으면 남은 색 중 첫 번째로 바꾼다.

### 사진 받기

- 브라우저(app.js): 고른 사진을 가운데 정사각형으로 잘라 256×256 JPEG(품질 0.85)로 그려 보낸다. HEIC 는 기존 사진 칸과 같은 방식으로 처리(브라우저가 못 읽으면 서버가 Pillow 로 시도, 안 되면 "이 사진은 열 수 없어요. 다른 사진을 골라 주세요.").
- 서버: 2MB 넘으면 거절("사진이 너무 커요. 다른 사진을 골라 주세요."). Pillow 로 열어 가운데 정사각형·256px 로 **다시 저장(JPEG, EXIF 없음)** — 위치 정보가 남지 않게. 이미지가 아니면 같은 "열 수 없어요" 문구.
- `GET /me/avatar/<user_id>.jpg` `avatar`: 로그인, **나 또는 내 커플 상대**만(아니면 404), 사진 없으면 404. `Content-Type: image/jpeg`, `Cache-Control: private, max-age=31536000` (주소에 `?v=<avatar_version>`).

### 프로필 화면

- 우리 화면 내 동그라미 밑 "프로필 바꾸기" → `GET|POST /me/profile/` `profile`.
  - 미리 보기 동그라미(지금 모습).
  - **사진**: 사진 고르기 / 사진 빼기.
  - **이모지**: 자주 쓰는 이모지 40개 격자 + "직접 넣기" 칸(1~16자, 띄어쓰기·영문·숫자 없음: "이모지 하나만 넣어 주세요."). "이모지 빼기".
  - **내 색**: 6색 견본. 상대가 쓰는 색은 흐리게, 고를 수 없음(서버도 거절: "상대가 쓰고 있는 색이에요. 다른 색을 골라 주세요.").
  - 닉네임은 지금처럼 우리 화면 "프로필 수정" 에 둔다.
- 저장하면 우리 화면으로, "프로필을 바꿨어요."

### 보이는 곳

- 템플릿 태그(또는 include) `{% avatar person size %}` 하나로 그린다: 사진이면 `<img class="av" src=…>`, 이모지면 `<i class="av" style="--c: var(--<color>)">😀</i>`, 아니면 `<i class="av" style="--c: var(--<color>)"></i>`. `.av` 바탕은 `var(--c)` 그라데이션.
- 바꿀 곳: `layout_app.html` 사이드바, `home.html` 우리 버튼, `us.html` 두 사람, `taste_detail.html` 댓글(글쓴이 기준), `_invite.html`·`connect.html` 의 나(상대 자리는 지금처럼 `?`).
- 일정 줄(`_event_item.html`): `<span class="by"><i class="dot" style="background: var(--<만든 사람 color>)"></i>나</span>` / 상대 이름. 공통 일정에만(지금처럼).

## 빌더에게 맡기는 것

- 이모지 40개 목록(커플·데이트·동물·음식 위주), 프로필 화면 배치.
- 사용자 목록을 불러올 때 `avatar` 바이트는 `defer()` 로 빼 두기, 사이드바·홈에 상대를 넘기는 방법(컨텍스트 프로세서 또는 `partner`).
- 이모지를 고르면 사진은 그대로 두고(사진이 먼저 보임), 사진을 빼야 이모지가 보인다 — "사진 빼기" 는 따로 누른다. (내 판단)
- 아바타 그리는 방법(템플릿 태그 vs include).

## 내가 정한 것 (사용자 확인 필요)

- 처음 색은 먼저 가입한 사람 장미, 상대 하늘. 같은 색은 못 고름.
- 사진은 가운데 정사각형으로 자동으로 자른다. 원본은 남기지 않는다.
- 올린 사진의 위치 정보(EXIF)는 지운다.
- 프로필 사진은 나와 상대만 볼 수 있다.
