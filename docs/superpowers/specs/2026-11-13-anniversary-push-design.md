# 기념일 알림 (웹 푸시) 설계

2026-11-13 · 상태: 검토 중

## 왜

두 사람이 기념일을 놓치지 않게, 기념일이 다가오면 각자의 폰에 알림을 보낸다.
지금은 앱을 열어야만 D-day 를 볼 수 있다.

## 목표

- 기념일 **당일**에는 반드시 알림이 간다 (끌 수 없음, 단 기기에서 알림을 허용한 경우).
- **하루 전**, **일주일 전** 알림은 사람마다 켜고 끌 수 있다. 한 사람의 설정은 상대에게 영향이 없다.
- 대상: 자동 기념일(사귄 날 기준 100일 단위·주년)과 직접 등록한 기념일(매년 반복 포함) 모두.
  계산은 지금 화면과 같은 `anniversaries/services.py` 를 쓴다.
- 커플 두 사람 모두에게, 각자 알림을 켠 모든 기기로 보낸다.

## 하지 않는 것

- 일정(캘린더) 알림, 하루에 여러 번 보내기, 기념일마다 따로 켜고 끄기, 이메일·카카오톡 알림.
- 오프라인 캐시 등 서비스 워커의 다른 기능.

## 이러면 실패 (기술적으로 동작해도)

- 같은 알림이 같은 날 두 번 온다.
- 과금이 생긴다 (CLAUDE.md: 무료 한도를 넘으면 안 된다).
- 아무나 알림 보내기 주소를 불러 알림을 보낼 수 있다.
- 알림 준비(열쇠)가 안 된 상태에서 사이트가 500 으로 깨진다.

## 제약

- Vercel Hobby Cron: **하루 한 번**, 정한 시(hour) 안의 아무 때나 실행된다 (최대 59분 늦음). 시간대는 UTC.
- 아이폰: iOS 16.4 이상, **홈 화면에 설치한 앱**에서만, 사용자가 버튼을 눌러 허용해야 한다.
- 모델을 바꾸므로 운영 DB(Neon)에 migrate 가 필요하다. 집 맥에서 한다 (`ENV_FILE=.env.neon`).
- 비밀 값(VAPID 개인 키, CRON_SECRET)은 채팅에 출력하지 않는다.
- 학원 PC 에서도 개발 서버가 떠야 한다: 열쇠가 없으면 알림 기능만 숨긴다.

## 방법 (고려한 것)

| 방법 | 장점 | 단점 |
|---|---|---|
| **Vercel Cron → Django 주소 (선택)** | 설정이 `vercel.json` 한 곳, 이미 쓰는 Vercel 안에서 끝남, CLAUDE.md 에 정해 둔 방식 | 하루 한 번, 실행 시각이 최대 59분 늦음 |
| GitHub Actions 예약 실행 → Django 주소 | 하루 여러 번 가능 | 설정·비밀 값이 GitHub 에 하나 더, 예약 실행도 수십 분 늦어지곤 함 |
| 서버 없이 기기에서 예약 알림 | 서버 불필요 | 웹에는 앱이 닫혀 있을 때 예약 알림을 띄우는 표준 기능이 없음 |

사용자가 **Vercel Cron** 을 골랐다. 알림이 하루 한 번 아침쯤이면 충분하기 때문.

## 사용자가 정한 것

- 당일 알림은 항상, 하루 전·일주일 전은 사용자가 선택.
- Vercel Cron 으로 하루 한 번.

## 설계

### 흐름

1. 사용자가 "우리 › 알림" 화면에서 **이 기기에서 알림 받기**를 누른다 → 브라우저가 허용을 묻는다
   → 허용하면 브라우저가 만든 구독 정보(endpoint, 열쇠 2개)를 서버에 저장한다.
2. Vercel Cron 이 매일 **UTC 00시(한국 오전 9시~9시 59분)** 에 `GET /cron/anniversaries/` 를 부른다.
   Vercel 이 `Authorization: Bearer <CRON_SECRET>` 를 붙여 보낸다. 다르면 401.
3. 서버는 커플마다 오늘(한국 날짜) 기준 0일·1일·7일 뒤인 기념일을 찾고,
   두 사람 각각에 대해 (당일은 항상, 1일·7일은 그 사람이 켰을 때만) 그 사람의 모든 기기로 푸시를 보낸다.
4. 서비스 워커가 알림을 띄우고, 누르면 기념일 화면(`/anniversaries/`)을 연다.

### 저장 (새 모델, 마이그레이션 → 맥에서 Neon migrate)

- `User` 에 두 칸: `notify_day_before`, `notify_week_before` (Boolean). 테마처럼 계정에 둔다.
- `PushSubscription`: 사용자, endpoint(유일), p256dh, auth, 만든 때. 기기(브라우저)마다 하나.
  푸시 서비스가 404·410 을 돌려주면(구독이 끝남) 지운다.
- `PushLog`: 사용자, 알림 열쇠(문자열), 보낸 날. (사용자, 열쇠) 유일.
  열쇠 예: `anniv:12:2026-12-24:7` (등록한 기념일 id·날짜·며칠 전), `auto:500일:2027-03-28:0`.
  Cron 이 두 번 불려도 같은 알림을 다시 보내지 않는다. 60일 넘은 기록은 Cron 이 지운다.

### 주소

- `GET /cron/anniversaries/` — Cron 전용. 결과 개수를 JSON 으로 돌려준다. `CRON_SECRET` 이 없으면 항상 거절.
- `GET|POST /me/notifications/` — 알림 화면과 하루 전·일주일 전 설정 저장.
- `POST /me/notifications/subscribe/`, `POST /me/notifications/unsubscribe/` — 이 기기 구독 저장·삭제 (JSON, CSRF 적용).
- `POST /me/notifications/test/` — 내 기기들로 시험 알림 보내기.

### 화면: 우리 › 알림

- "우리" 의 설정 메뉴에 "알림" 줄 추가 (캘린더 앱에서 보기와 같은 방식의 하위 화면).
- 이 기기 상태: 받는 중 / 꺼져 있음 / 이 브라우저는 안 됨 / 아이폰인데 홈 화면 앱이 아님("홈 화면에 추가한 앱에서 켤 수 있어요") / 브라우저에서 막음("설정에서 알림을 허용해 주세요").
- 버튼: 이 기기에서 알림 받기 · 끄기, 시험 알림 보내기.
- 스위치: 하루 전 알림, 일주일 전 알림. 당일 알림은 "기념일 당일에는 항상 알려 드려요" 문구로만.
- 열쇠(VAPID)가 설정되지 않은 서버에서는 메뉴 줄을 숨긴다.

### 알림 문구 (부드러운 존댓말, 받침에 따라 이에요/예요)

- 당일: 제목 "오늘은 500일이에요", 본문 "함께한 날을 축하해요"
- 하루 전: "내일은 500일이에요"
- 일주일 전: "500일까지 일주일 남았어요"
- 직접 등록한 기념일은 이름을 그대로 쓴다 ("오늘은 바다 생일이에요").
- 같은 사람에게 같은 날 여러 기념일이 겹치면 각각 따로 보낸다 (드문 일).

### 열쇠와 환경 변수 (Vercel Production)

- `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`(`mailto:` 주소), `CRON_SECRET`.
- 열쇠 만들기: 관리 명령 `python web/manage.py make_vapid_keys` 가 `.env` 에 붙여 넣을 줄을 출력한다
  (사용자가 직접 실행, 채팅에 출력하지 않는다). 개발용 `.env` 와 운영용은 따로 만든다.
- 라이브러리: `pywebpush` 를 requirements 에 더한다.

### 무료 한도

- 웹 푸시 발송은 무료(브라우저 회사의 푸시 서비스). Cron 은 Hobby 에 포함. Neon 에 행이 조금 는다.
- R2 는 쓰지 않는다.

## 빌더에게 맡기는 것

- 모델을 둘 앱 (`accounts` 또는 새 `notifications` 앱), 코드 배치, 테스트 구성.
- 푸시 보내기 실패(네트워크 등) 시 재시도 여부 — 한 번 시도하고 기록하지 않으면 다음 날 Cron 이 다시 보내지 않으므로, **보내기에 성공한 것만 PushLog 에 남긴다**는 원칙만 지킨다.
- 시험 알림 문구, 알림 아이콘(기존 `icons/icon-192.png`).

## 내가 정한 것 (사용자 확인 필요)

- 하루 전·일주일 전 알림의 **기본값은 꺼짐**.
- 보내는 시각: 한국 오전 9시대.
- 알림 설정은 "우리 › 알림" 하위 화면에.
