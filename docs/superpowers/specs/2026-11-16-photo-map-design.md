# 사진 지도 설계

2026-11-16 · 상태: 검토 반영, 승인 대기

## 왜

두 사람이 함께 간 곳을 실제 지도에서 한눈에 보고 싶다. 직접 핀을 찍는 수고 없이, 이미 올리는 데이트 사진의 촬영 위치로 지도를 채운다.

## 목표

- 사진을 올릴 때 촬영 위치(위도·경도)를 함께 저장한다.
- 앨범 탭에 세 번째 칸 **지도** (`전체 사진 · 앨범 · 지도`).
- 지도 안에서 **국내 · 해외** 전환.
  - 국내: **카카오맵**. 간 시·군·구를 색칠, 사진 위치에 핀.
  - 해외: **Leaflet + OpenStreetMap**. 간 나라를 색칠, 사진 위치에 핀.
- 색칠은 테마 색(`--primary` 계열)으로, 그 지역 사진이 많을수록 조금 더 진하게.
- 가까이 몰린 핀은 숫자 묶음(클러스터). 핀·묶음을 누르면 그 자리 사진들이 아래에 뜨고, 사진을 누르면 사진 화면(`photo_detail`).
- 이미 올린 사진 중 원본 그대로 저장된 것은 서버에서 위치를 다시 읽어 채운다.

## 하지 않는 것

- 위치 없는 사진에 위치를 직접 넣는 기능, 지도에서 직접 핀 찍기, 일정 장소를 지도에 올리기.
- 경로·이동선, 히트맵, 지도 공유.
- 카카오맵과 다른 지도 타일을 한 화면에 섞기 (카카오 약관상 안 됨).

## 이러면 실패 (기술적으로 동작해도)

- 과금이 생긴다 (구글·네이버 지도는 카드 등록이 필요해서 쓰지 않는다. 카카오·OSM 은 무료 한도 안).
- 사진 위치가 커플 밖으로 새어 나간다 (위치는 민감 정보: 그 커플 두 사람만 본다).
- 위치를 읽다가 사진 올리기가 실패하거나 느려진다 (위치는 덤이다. 못 읽으면 위치 없이 올라간다).
- 카카오 키가 없는 서버(학원 PC 개발 서버 등)에서 지도 화면이 깨진다.

## 제약

- 사진은 브라우저가 1.5MB 넘으면 긴 변 2560px JPEG 로 줄여 보낸다 (`app.js`). 줄이면 사진 정보(EXIF)가 지워진다 → **줄이기 전에** 브라우저에서 읽는다. 지금 촬영일(`exifDate`)을 이미 그렇게 읽고 있다.
- 폰 사진 선택기가 위치를 지우고 넘길 수 있다 (아이폰 공유 옵션, 안드로이드 사진 선택기). 실제로 얼마나 남는지는 폰 시험에서 본다. 위치 없는 사진이 많아도 지도는 동작해야 한다.
- 모델이 바뀐다 → Neon migrate 를 배포보다 먼저 (집 맥).
- R2: 목록 조회(LIST) 금지. 위치 채우기는 DB 에 있는 사진만 하나씩 읽는다(GET, 무료 한도 넉넉).
- 사진 주소는 1시간 서명 주소.
- 외부 스크립트는 정확한 버전을 고정한다.

## 방법 (고려한 것)

| 방법 | 장점 | 단점 |
|---|---|---|
| Leaflet + OSM 하나로 | 키·카드 없음, 해외도 됨, 코드 한 벌 | 한국 지도가 덜 익숙 |
| 카카오맵 하나로 | 한국 지도가 익숙·자세함 | 해외가 거의 빈 지도 |
| **국내 카카오맵 + 해외 Leaflet (선택)** | 둘의 장점 | 지도 라이브러리 두 벌, 할 일 1.5배, 카카오 JavaScript 키 필요 |
| 구글·네이버 지도 | 둘 다 국내외 됨 | 카드 등록 필요 → 과금 금지 원칙 위반 |

사용자가 **국내 카카오맵 + 해외 Leaflet** 을 골랐다. 국내는 익숙한 지도로, 해외 여행도 담기 위해.

## 사용자가 정한 것

- 간 곳의 출처는 **사진 위치**.
- 국내 카카오맵, 해외 Leaflet+OSM, 지도 화면에서 전환.
- 위치: 앨범 탭 세 번째 칸. 색칠: 국내 시·군·구, 해외 나라. 사진 많을수록 진하게.
- 이미 올린 원본 사진은 위치 채우기. 위치 없는 사진은 지도에 안 나오고, 직접 넣는 기능은 이번에 안 함.

## 설계

### 저장

- `Photo.latitude`, `Photo.longitude` (FloatField, null). 마이그레이션 → Neon.
- 값 범위 검사: 위도 −90~90, 경도 −180~180, 둘 다 있거나 둘 다 없음. (0, 0) 은 위치 없음으로 본다 (잘못 기록된 사진에 흔함).

### 위치를 얻는 곳 (먼저 것 우선)

1. **브라우저**: 사진 정보 읽기 라이브러리 **exifr**(jsdelivr, 버전 고정, GPS만 읽는 가벼운 설정)로 JPEG·HEIC·PNG 의 GPS 를 읽고, 사진마다 `latitude`, `longitude` 를 폼 값으로 같이 보낸다. 한 장 올리기·여러 장 올리기·드라이브 가져오기 모두 같은 길을 탄다.
2. **서버**: 브라우저가 값을 안 보냈고 올라온 파일이 JPEG 등 Pillow 가 읽을 수 있는 형식이면 서버가 EXIF GPS 를 읽는다 (스크립트 없이 올린 경우, 줄이지 않은 원본). HEIC 는 서버에서 읽지 않는다 (`pillow-heif` 는 함수 크기 때문에 넣지 않는다) → 브라우저 읽기가 HEIC 를 맡는다.
   - 아이폰 Safari 는 `accept="image/*"` 로 고르면 보통 HEIC 를 JPEG 로 바꿔 넘긴다. 안드로이드·드라이브에서는 HEIC 그대로 올 수 있다.
3. **이미 올린 사진 채우기**: 관리 명령 `fill_photo_locations` 이 위치가 비어 있는 사진의 저장 파일을 하나씩 열어 2번과 같은 방법으로 읽는다 (줄였는지 표시가 없어서 모두 연다. 두 사람 규모라 GET 몇백 번, 무료 한도 안). `--dry-run` 으로 몇 장 채워질지 먼저 본다. 맥에서 `ENV_FILE=.env.neon` 으로 한 번 돌린다. 줄여서 저장된 사진은 위치가 이미 없어 건너뛴다.
- 사진 고치기(`photo_update`) 는 위치를 바꾸지 않는다. 사진 파일을 바꾸면 그 파일 기준으로 다시 정한다.

### 지도 데이터

- `GET /albums/map/data/` (로그인, 내 커플 사진만): 위치 있는 사진 목록 JSON `[{id, lat, lng, src, taken, url}]`. `src` 는 사진 원본의 서명 주소 (썸네일 파일은 따로 만들지 않는다). **지도를 그릴 때는 사진을 받지 않고**, 핀을 눌러 사진 줄을 띄울 때만 그 자리 사진을 `loading="lazy"` 로 받는다.
- 지역 경계는 정적 파일로 앱에 넣는다 (`static/geo/`):
  - 한국 시·군·구 경계 (단순화한 GeoJSON/TopoJSON, 공공 데이터 출처 하늘)
  - 세계 나라 경계 (Natural Earth 110m, 퍼블릭 도메인)
- 색칠할 지역은 **브라우저가** 점-다각형 포함 검사로 정한다 (서버·외부 API 호출 없음).
- 국내·해외 판정: 시·군·구 다각형 안이면 국내. 다각형 밖이어도 한국 바다 영역(위도 32.8~38.9, 경도 124.0~132.0 사각형 안이고 다른 나라 다각형 안이 아님: 해안선 단순화·섬·독도)이면 **국내 핀**으로 두고 색칠만 하지 않는다. 그 밖은 해외.
- 해외 나라 경계는 Natural Earth **50m**(작은 나라 포함)를 우선, 크기가 넘치면 110m. 경계에 안 걸리는 작은 나라·바다 위 사진은 핀만 보인다.

### 화면

- 앨범 세그먼트: `전체 사진 · 앨범 · 지도`. 지도 칸을 처음 열 때 데이터·지도 라이브러리·경계 파일을 불러온다 (앨범 첫 화면 속도에 영향 없게).
- 지도 칸 위쪽에 `국내 · 해외` 전환, 각 칸에 "N곳 · 사진 M장" 요약.
- 국내: 카카오맵 SDK(`autoload=false`, `clusterer` 라이브러리), 시·군·구 다각형, 핀 클러스터.
- 해외: Leaflet + markercluster (cdnjs, 버전 고정), OSM 타일 + 출처 표기, 나라 다각형.
- 핀·묶음을 누르면 지도 아래 사진 줄(가로 스크롤)에 그 자리 사진, 누르면 `photo_detail`.
- 사진 화면(`photo_detail`)에 위치가 있으면 "지도에서 보기" 링크(지도 칸으로, 그 사진 위치로 이동), 없으면 "위치 없음".
- 빈 상태: "위치가 있는 사진이 아직 없어요. 사진을 올릴 때 촬영 위치가 함께 저장돼요."
- 라이트·다크, 배·여정에서 색칠 색과 핀 색이 토큰을 따른다.

### 키와 무료 한도

- 새 환경 변수 `KAKAO_JS_KEY` (카카오 앱의 JavaScript 키, 콘솔 "플랫폼 키"의 JavaScript 키에 사이트 도메인 등록: 배포 주소, `http://localhost:8000`).
- **`KAKAO_JS_KEY` 가 없거나 카카오 SDK 를 불러오지 못하면(도메인 미등록 등, 5초 제한) 국내도 Leaflet 으로 그린다** — 시·군·구 색칠과 핀도 Leaflet 위에 같은 방식으로. 메뉴는 그대로 보인다.
- 카카오맵 지도 표시는 무료 한도가 넉넉하다 (두 사람 규모). OSM 타일은 사용 정책상 소량·출처 표기면 된다.

## 빌더에게 맡기는 것

- 한국 시·군·구 경계 파일의 출처(공공 데이터, 라이선스 표기) 선택과 단순화. 쓸 만한 시·군·구 파일을 크기 안에서 못 구하면 **시·도 단위로 낮춰도 된다** (MEMO 에 적는다). 경계 파일의 구체적인 단순화 정도 (전체 크기 목표: 둘 합쳐 1.5MB 이하, 지도 칸을 열 때만 받음), 형식(GeoJSON/TopoJSON).
- 클러스터 묶는 거리, 색 진하기 단계, 사진 줄 레이아웃.
- 서버 EXIF 읽기 구현 (Pillow `getexif()` GPS IFD).

## 내가 정한 것 (사용자 확인 필요)

- 위치 읽기는 exifr 라이브러리 (HEIC 도 읽음). 서버는 HEIC 를 읽지 않는다.
- 썸네일 파일을 만들지 않고, 핀을 누를 때만 그 자리 사진을 받는다.
- 해안·섬처럼 경계에 안 걸리는 한국 사진은 국내 핀(색칠 없음).
- 시·군·구 경계 파일을 못 구하면 시·도 단위로.

- `KAKAO_JS_KEY` 가 없으면 국내도 Leaflet 으로 (깨지지 않게).
- (0, 0) 위치는 위치 없음으로 본다.
- 지도 데이터와 라이브러리는 지도 칸을 열 때만 불러온다.
