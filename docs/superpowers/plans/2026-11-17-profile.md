# 프로필 묶음 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 각자 프로필(사진·이모지·내 색)을 정하고, 아바타는 사람마다 같은 모습으로, 일정의 만든 사람 표시는 그 사람 색 점으로.

**Architecture:** `accounts.User` 에 color/emoji/avatar(BinaryField)/avatar_version. 사진은 브라우저가 256px 로 줄이고 서버가 Pillow 로 다시 저장(EXIF 없음)해 DB 에 둔다. 아바타는 템플릿 태그 하나로 그린다.

**Tech Stack:** Django 5.2, Pillow, 바닐라 JS (`static/js/app.js`), `static/css/app.css`.

**Spec:** `docs/superpowers/specs/2026-11-17-profile-design.md`

## Global Constraints

- 문구 존댓말, 주석 한국어, 색은 토큰. 375px·라이트/다크·배/여정.
- 마이그레이션 `accounts.0004_profile`(스키마 + 기존 사람 색 채우기) → Neon 확인 숫자 **53**, 배포보다 먼저.
- 색 6가지: sky·rose·sand·lav·sage·peach. 처음: 커플 안 `date_joined`(같으면 pk) 순 첫 사람 rose, 둘째 sky, 커플 없으면 rose.
- 사진: 서버 2MB 까지, 256×256 가운데 정사각형 JPEG 로 다시 저장(EXIF 없음). 이미지 아님 → "이 사진은 열 수 없어요. 다른 사진을 골라 주세요.", 큼 → "사진이 너무 커요. 다른 사진을 골라 주세요.".
- 상대가 쓰는 색 거절: "상대가 쓰고 있는 색이에요. 다른 색을 골라 주세요."; 이모지 검사 실패: "이모지 하나만 넣어 주세요."
- 테스트 `cd web && ../.venv/bin/python manage.py test`. 브랜치 `feat/profile`.

## Review Focus

1. 다른 커플 사람의 `/me/avatar/<id>.jpg` → 404 (Task 1 테스트).
2. GPS EXIF 가 든 JPEG 를 올리면 저장된 바이트에 EXIF 가 없다 (Task 1 테스트).
3. 초대 코드로 들어온 사람의 색이 상대와 같으면 다른 색으로 바뀐다 (Task 1 테스트).
4. 커플 목록·일정 목록에서 avatar 바이트를 불필요하게 읽지 않는다 — 일정 줄 `select_related("created_by")` 가 avatar 를 끌고 오지 않게 `defer("created_by__avatar")` (Task 2 테스트로 쿼리 SQL 에 avatar 없음 확인).
5. 사진 있는 사람이 이모지를 골라도 사진이 그대로 보이고, "사진 빼기" 뒤 이모지가 보인다 (Task 1 테스트).

### Task 1: 프로필 저장·화면·사진 주소

**Files:** Modify `web/accounts/models.py`, `accounts/views.py`, `accounts/urls.py`, `accounts/forms.py`(새로 만들어도 됨), `web/couples/views.py` (`join`: 색 겹침 처리), `templates/couples/us.html`(프로필 바꾸기 링크); Create `accounts/migrations/0004_profile.py`, `accounts/avatars.py` (`clean_avatar`), `templates/accounts/profile.html`; Modify `static/js/app.js` (프로필 사진 256px 정사각형 줄이기), `static/css/app.css`; Test `web/accounts/tests.py` 또는 `couples/tests.py` 의 `ProfileTests`

**Interfaces — Produces:**
- `User.color` (Char 10, choices 6색, default "sky"), `User.emoji` (Char 16, blank), `User.avatar` (BinaryField null, editable=False), `User.avatar_version` (PositiveInteger 0).
- `User.avatar_url` property: 사진 있으면 `reverse("avatar", args=[pk]) + f"?v={avatar_version}"`, 없으면 `""`. (`avatar` 필드를 읽지 않고 판단하도록 `has_avatar = BooleanField(default=False)` 를 함께 둔다 — 지연 로딩 때문.)
- `accounts.avatars.clean_avatar(data: bytes) -> bytes` — 2MB 넘으면 `ValueError("too_big")`, 열 수 없으면 `ValueError("bad")`, 아니면 가운데 정사각형 256px JPEG(품질 85) 바이트, EXIF 없음.
- `accounts.avatars.free_color(partner) -> str` — 상대 색이 아닌 첫 색(목록 순).
- 주소: `me/profile/` `profile` (GET/POST), `me/avatar/<int:pk>.jpg` `avatar` (GET).
- 프로필 폼 POST 필드: `photo`(파일, 선택), `remove_photo`("1"), `emoji`(문자, 빈 값이면 빼기), `color`.

**Interfaces:**

- Produces: `{% avatar person "big"|"" %}` (simple_tag, `format_html` 로 안전하게): 사진 → `<img class="av [big]" src="…" alt="">`, 이모지 → `<i class="av emoji [big]" style="--c: var(--<color>)">🐻</i>`, 둘 다 없음 → `<i class="av [big]" style="--c: var(--<color>)"></i>`. `person` 이 None 이면 빈 자리 `<i class="av vacant [big]">?</i>`.
- `.av` 바탕 `linear-gradient(160deg, var(--c), color-mix(in srgb, var(--c) 55%, var(--surface)))`, `img.av` 는 `object-fit: cover`. 기존 `.av.a`/`.av.b` 는 지운다.
- 일정 줄: `<span class="by"><i class="dot" style="background: var(--{{ event.created_by.color }})"></i>나</span>` (상대는 이름).
- 사이드바·홈은 `user` 와 `user.partner` 를 쓴다.
