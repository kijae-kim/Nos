# 써 보며 나온 것 2차 — 수정 계획 (2026-11-25)

사용자 메모 7가지를 세 단계로 나눈다. 모델이 바뀌는 것은 2단계의 앨범 대표 사진(마이그레이션 1개)뿐이다.

## 사용자가 정한 것

- 튜토리얼: **처음 한 번 장면 넘기기** (3~5장, 우리 › 사용법에서 다시 보기)
- 업데이트 노트: **새 소식이 있을 때 한 번 팝업** + 우리 › 업데이트 소식에 모음 (사람마다 본 것 기억)
- 앱처럼 쓰기 버튼: **로그인 화면 + 우리** (이미 홈 화면 앱으로 쓰는 중이면 숨김)

## 1단계 — 바로 고칠 것 (모델 안 바뀜)

1. **메모 펜 버튼이 손가락을 안 따라옴** (아이폰)
   - 의심: 끄는 동안에도 `visualViewport` 의 scroll·resize 가 `place()` 를 불러 저장된 위치로 되돌림, 자판이 떠 있을 때 고정 위치 기준이 보이는 화면과 어긋남.
   - 고칠 것: 끄는 동안에는 `place()` 를 멈추고, 위치를 보이는 화면 기준으로 계산. 아이폰에서 직접 확인(사용자).
2. **태그를 누르면 버벅임**
   - 서버는 빠름 (로컬에서 쿼리 15개, 15ms). 느린 건 캘린더 화면 전체를 다시 불러오기 때문(배포 서버 왕복 + 달력 다시 그리기).
   - 고칠 것: 태그 모아 보기를 화면 전체 대신 목록 조각만 받아 바꿔 끼우기(주소는 그대로 바뀌게), 누른 칩은 바로 눌린 모양으로.
3. **단어 정리 (이름표 → 태그 포함)**
   - 먼저 화면 문구 전수 조사표를 만든다: 지금 '고치기' 22곳, '수정' 2, '바꾸기' 7, '지우기' 11, '삭제' 2, '이름표' 18, '태그' 5 …
   - 조사표와 통일안(예: 고치기→수정, 지우기→삭제 또는 그대로, 이름표→태그 / @카테고리·#태그 구분은?)을 사용자에게 보여 주고 **결정 받은 뒤** 한꺼번에 바꾼다.

## 2단계 — 작은 기능

4. **앨범 대표 사진**
   - `Album.cover` (사진, 비워 두면 지금처럼 최근 사진). 사진 보기 화면 메뉴에 '앨범 대표 사진으로', 앨범 고치기 화면에서도 고르기.
   - 대표 사진이 앨범에서 빠지거나 지워지면 자동으로 비움. 마이그레이션 1개 → Neon migrate.
5. **앱처럼 쓰기 버튼**
   - 안드로이드 크롬: 브라우저가 주는 설치 창(`beforeinstallprompt`)을 버튼으로 바로 연다.
   - 아이폰: 웹에서 설치 창을 열 수 없어서, 누르면 '공유 → 홈 화면에 추가' 그림 안내 판.
   - 홈 화면 앱으로 열려 있으면(`display-mode: standalone`) 버튼을 숨긴다.

## 3단계 — 안내

6. **처음 한 번 튜토리얼**: 로그인 후 처음 홈에서 장면 3~5장 (+ 버튼 / 날짜 누르기·글로 일정 / 추억·메모 펜 버튼 / 홈 화면에 추가). 본 것은 계정에 기억(기기를 바꿔도 다시 안 뜸). 우리 › 사용법에서 다시 보기.
7. **업데이트 소식**: 소식 목록은 코드 안 파일(날짜·제목·몇 줄)로 관리 → 새 소식이 있으면 앱을 열 때 한 번 팝업, 우리 › 업데이트 소식에 전체. 본 마지막 소식은 계정에 기억(마이그레이션은 4와 함께 한 번에).

## 순서

1단계(1·2 → 3의 조사표·결정 → 3 적용) → 2단계(4·5, Neon migrate) → 3단계(6·7). 단계마다 배포.
